# 不確かな面法線からの過剰な構造拘束

`final-saturation-lio`（面品質による構造判定なし）は、510秒のX速度−1.45 m/sから
515秒には+0.10 m/sへ変わり、その間の水平移動を約9 m過小に推定した。
帰着部屋のNN中央値は4.842 mとなり不採用。状態・共分散が有限でも精度は破綻し得る。
以前の同設定のビルドはこの区間を通過できたが、微小な数値差で対応選択が分岐した。
そのため、良かった1実行だけを最終結果として採用しない。

約511秒の保存スキャンからvoxel面を再計算すると、廊下の進行方向（ほぼ世界X）を向く
面は1つで、支持は6点、方向はX軸から約4度、法線の最大方向標準偏差は約11.9度だった。
標準偏差は点雑音0.03 mと面の点分布から計算した近似で、真の角度誤差ではない。
保存点群はfrontendの点を1点おきに抽出したものであり、この支持数・標準偏差は
実行時に使った全点の面を厳密に再現した値ではない。問題のある幾何形状を示す補助的な根拠である。
他の510、512、513、514秒付近の保存スキャンには、この方向の構造面候補がなかった。

従来の構造判定は平均法線の方向が軸から8度以内なら、生成時に0.01度の方向priorを
与えていた。支持点の平面らしさだけでは、細長い点分布からの法線の不確かさは分からない。
このような面で高精度の方向を作ることは、実際には弱い廊下方向の観測を強く扱うことになる。

追加した判定は `structural_landmarks=true` と `plane_uncertainty=true` の組み合わせで有効：

- 平均法線と最も近い軸との角度に、法線共分散の最大標準偏差の2倍を足す。
- この値が構造判定の角度以内のときだけ、新しい構造方向priorを作る。
- 信頼できるpatchを先に処理し、弱いpatchは確立済みの面へ対応できる。
- 確立済みの面がなければ、法線・距離を自由に推定する一般面として残す。点を一律に捨てない。
- 信頼できる構造観測が自由面へ吸収され、方向priorを迂回することは引き続き防ぐ。

狭い6点の平面が偽の方向priorを作らないこと、既存面を観測できること、
並べ替え後も生点とdeskew Jacobianの対応が維持されることを試験した。
C++試験13件成功（`ctest-plane-confidence.txt`）。
`plane-confidence-lio` / `plane-confidence-bias` は完走したが、512秒後の速度低下は残った。
品質判定だけで実bagの問題が解決したとはいえない。飽和時の分散2500による速度共分散の急増も
調べ、分散100との組み合わせで共通壁の差11.6–15.0 cmまで改善した候補を得た。
[飽和分散の分析](IMU_SATURATION.md)と[全区間の比較](../../ONLINE_RECONSTRUCTION.md)を参照。
推定器に511秒などの時刻条件や帰着位置は入れていない。


## 反復で残った廊下方向の移動量の差

分散100の最初の実行は帰着壁差12–15 cmまで改善したが、同一バイナリ・設定の反復では
X壁差88 cmとなった。512秒の失速は両方で抑制されており、これだけが残差の原因ではない。

元bagの廊下16スキャンを全点で抽出し、0.5 m voxelの面候補を確認した。
15スキャンでは、世界X方向を向く十分な品質の面候補がなかった。
450秒付近の1スキャンには候補が1面あり、200面への均等選択で失われる例もあった。
ただし、多くの場所では候補選択前からその方向の面が乏しく、間引きだけの問題とはいえない。
壁・床の法線を使う観測は、それらに沿う並進を強く測れない。
IMUの小さな速度誤差が、このような長区間の移動量へ蓄積する可能性がある。

[全点スキャンでの数値](plane-sampling-full-raw.json)。この確認は歪み補正前の元点群と
保存された姿勢による幾何形状の補助検査であり、実行時の対応を厳密に再現していない。
時刻を間引いた16スキャンで、全走行のすべての観測が不能と証明したものでもない。
時間窓延長と弱い方向への画像融合を比較し、追加の観測が残るずれを抑えられるか確認する。
