# 時間窓によるLiDAR・IMU同時推定

`feat/temporal-lio-window`（親・fast-livo2内部の両リポジトリ）に、姿勢・位置・速度・gyro bias・accel biasを複数時刻で同時推定する経路を追加した。従来のX-ICP付きIEKFと切り替えて使う。既存の未コミット変更は維持している。

**2026-09-30の全区間比較と最新の実行設定は [オンライン再構成の検証](ONLINE_RECONSTRUCTION.md) を参照。**
以下の初期検証・9月29日の分析は経緯として残す。現在は初期化の切り分けを経て、
生点のdeskew微分、面と状態の同時推定、IMU飽和、面方向の不確かさを検証している。
`--temporal-window on` だけでは、この比較で使う設定一式にはならない。

この変更の目的は、現在のスキャンの位置合わせだけでは区別しにくい姿勢・重力補償・biasの不整合を、時間をまたぐIMU拘束で評価することにある。**時間窓の導入自体は、観測不能な進行方向の速度やbiasを必ず回復できる保証にはならない。** 実データの判定は別途検証記録に残す。

## 実行

通常のROSコンテナ内で、ビルド済みワークスペースを使う。

```bash
cd /external
bash scripts/fast_livo2/reconstruct_raw.sh bags/raw_20260907_114335 \
  --lio-only --temporal-window on --capture-diagnostics --rate 0.25
```

再生用ROSドメインの既定値は42。同じドメインに前回の`/laserMapping`が残っている場合は、
起動・bag再生前に停止する。前回の実行を終了するか、未使用ドメインを指定する。
このスクリプトの指定は`ROS_DOMAIN_ID`ではなく`FAST_LIVO2_RECONSTRUCTION_DOMAIN_ID`を使う。

```bash
FAST_LIVO2_RECONSTRUCTION_DOMAIN_ID=43 \
bash scripts/fast_livo2/reconstruct_raw.sh bags/raw_20260907_114335 \
  --lio-only --temporal-window on --capture-diagnostics --rate 0.25
```

同名ノードが複数あると、`ros2 param dump /laserMapping`は取得対象を一意に定められない。
`Temporal parameter mismatch`は再ビルド不足だけでなく、この競合でも発生する。
2026-09-28の`110428`実行では新バイナリは時間窓を有効に起動していたが、
ドメイン42に`093848`実行の旧バイナリが残存していた。旧ログは変更せず、別ドメインで再実行する。

`effective parameter dump unavailable`と表示された場合、capture内の`param_dump.stderr`に
取得失敗の理由が保存される。`112549`実行ではROS CLI daemonがXML-RPC経由で`!rclpy.ok()`を返していた。
再生スクリプトとヘッドレス検証は、パラメータ取得にも`--no-daemon --spin-time 2`を使うよう修正済み。
直接の発見と全パラメータ取得に15秒の上限を設け、再生スクリプトでは各試行のエラーと終了コードも保存する。
これはPython・shellの修正なので、C++の再ビルドは不要。

`--temporal-window on` は派生YAMLに設定を保存する。LiDARはスキャン単位のvoxel-planeを使い、従来LiDAR IEKF・X-ICP更新を置き換える。較正、3秒の静止IMU初期化、加速度スケール、IMU雑音の設定値は引き継ぐ。`imu.imu_en=true`、`imu.ba_bg_est_en=true`、`imu.gravity_est_en=false`が必要。

## 推定する状態と拘束

時刻ごとの15変数は `[δθ, p, v, bg, ba]`。回転は右摂動、位置・速度・重力はworld座標、biasはIMU座標。重力ベクトルは初期化後に固定する。既存19状態との受け渡しでは露光・重力を固定変数として扱い、推定対象15変数の相互共分散を転送する。

- 全LiDARスキャン間のIMUを中点積分し、回転・位置・速度・両biasの15次元残差で隣接状態を結ぶ。積分開始・終了のサンプルを補間する。同期処理が残した最初の未来IMUも読んで、スキャン終端の補間に使う。
- 最新スキャンを直前の保持キーフレームの面と照合する。面の取得側の姿勢も同時推定する。1つのスキャンを複数の地図コピーへ重複して拘束しない。
- raw点・点ごとの時刻・raw IMUを保持し、外側反復ごとに修正後の姿勢・速度・biasで歪み補正と面推定をやり直す。
- 一時的な減衰は最適化のステップにだけ使う。共分散と周辺化には減衰項を入れない。
- 状態の予測には、時間窓の直前の推定状態を使う。従来の`StateEstimation()`を適用した事後分布や固定地図を、追加の独立観測として投入しない。

IMU残差は、`ΔR, Δp, Δv`を予積分値として以下を用いる。

```text
rR  = Log(ΔR(bg_i)^T R_i^T R_j)
rp  = R_i^T (p_j - p_i - v_i dt - 0.5 g dt²) - Δp(bg_i, ba_i)
rv  = R_i^T (v_j - v_i - g dt) - Δv(bg_i, ba_i)
rbg = bg_j - bg_i
rba = ba_j - ba_i
```

点`x_i`、参照面の法線`n_j`・中心`c_j`に対するLiDAR残差は次の通り。

```text
rL = n_j^T (R_j^T (R_i x_i + p_i - p_j) - c_j)
```

IMUの雑音設定は既存実装に合わせ、離散サンプル分散を`dt²`で伝播する。新たな連続時間noise-density値へ読み替えていない。位置・速度の交差項、biasのrandom walkも保持する。予積分共分散の`1e-12`対角項は数値用の下限。

## 時間窓と周辺化

初期設定は`window_sec=6.0`、`keyframe_sec=0.5`、`max_nodes=16`、`iterations=3`。スキャン終端時刻の揺れにより実際のキーフレーム間隔は約0.5–0.6秒となる。6秒は開始用の設定であり、最適な窓長を同定した値ではない。

最新スキャンは毎回状態を持つ。直前の非キーフレームは、新スキャンとのIMU拘束を作って最適化した後で周辺化する。古いキーフレームも窓長・ノード数の上限に従って周辺化する。これにより毎スキャンの情報を使いながら保持量を制限する。

周辺化では、**既存priorと、削除対象に接続する因子だけ**を新しいpriorへ含める。残る因子を再びpriorへ含める二重計上を避ける。平方根形式のQR分解で削除変数を消去し、残る変数の平方根priorを保存する。最適化と事後共分散も平方根形式から計算する。条件の悪い正規行列の差で微小な情報を失う方式は採用していない。

窓外へ出た情報はその時点で線形化したpriorとして残る。窓外のraw点を再最適化する仕組み、ループ閉じ込み、全履歴のBAは含まない。

## 局所地図と観測モデルの範囲

参照面は各スキャンのIMU終端座標系に0.5mのvoxelを作ってPCAで推定する。単一スキャンの面と取得姿勢を関連付ける構成であり、従来のworld座標の永続`VoxelOctoTree`をそのまま固定参照する実装ではない。階層的octree検索はこの経路には含まない。

支持点6点以上、面らしさ・面内の広がりを確認し、近傍27voxelから対応を選ぶ。面の散らばりと有限支持数を分散へ反映し、点の標準偏差0.03mと合わせてHuber重みを使う。1面を参照する多数の点に対して、実効支持数を最大6点相当に制限する。これは過信を抑える近似であり、全スキャンをまたぐ共有面の完全な相互共分散モデルではない。

歪み補正と面推定は外側反復で更新し、内側の微分・ラインサーチでは固定する。raw点の時刻は保持し、異なる時刻を混ぜたvoxel重心をraw観測として再使用しない。歪み補正・面フィットそのものを全状態で解析微分する方式ではない。

`/Laser_map`は従来と同じ全走行の累積voxel地図を表示する。時間窓導入時に直近約6秒の局所地図へ変更したが、
ユーザーの指示で撤回した。各スキャンの出力時のworld点群を既存の`update_and_publish_map()`へ渡し、
`publish.map_voxel_size`と`publish.map_publish_interval`に従って蓄積・配信する。推定器の照合用地図とは独立。
`/path`には修正済みのキーフレーム履歴と最新の端点だけを出力し、修正されない中間姿勢との混在を避ける。
窓外のキーフレームは最後に報告された姿勢のまま保持する。全スキャンのオンライン推定値はCSV等に残る。
出力済みの点群・保存済みPCDを後から全て修正するものではない。PCDの累積表示を全履歴最適化済みの地図と扱わない。

Laser Mapは従来のIntensity表示、Volatile配信へ戻した。Registered ScanのDecay Timeも10秒へ復元した。
軌道はTransient Local配信とBuffer Length 1を維持し、修正前後の全軌道が重なる不具合を防ぐ。
復元理由・確認結果は[Laser Mapの表示仕様復元](LASER_MAP_DISPLAY_RESTORE.md)を参照。
2026-09-29の変更にはC++再ビルドとRViz設定の再読込みが必要。


## 検証項目

- 正常なIMUで静止状態を維持できること、IMU欠落・重複時刻を拒否すること。
- 回転・並進・非identity外部較正を含む歪み補正。
- 短時間の全状態保持と周辺化後の状態・共分散の一致。
- LiDAR拘束のない100秒間でも保持量を制限し、位置共分散が不自然に縮まらないこと。
- 床と平行壁しかない合成廊下で、観測不能な進行方向・加速度biasに架空の拘束を加えないこと。
- 180度を超える旋回と加減速で、既知のgyro bias・accel bias・速度を回復すること。
- world座標系を回転・並進してもbody biasと軌跡・共分散の変換が整合すること。
- 既存6件のC++回帰試験、captureの設定切替・誤設定拒否・専用ログ終了処理。

関連実装は`temporal_imu.cpp`、`temporal_planes.cpp`、`temporal_factors.cpp`、`temporal_window.cpp`、ROS接続は`LIVMapper_temporal.cpp`。

## 生の点群の微分と構造方向の比較設定

`lio.temporal.consistent_deskew: true` は、歪み補正が依存する姿勢・速度・両biasを点–面残差の微分に含める。現在スキャンと参照スキャンの両方を扱う。IMU軌道の節点で感度を計算し、各点の取得時刻へ補間する。並進はスキャン終端座標系の歪み補正では相殺する。参照面の中心・法線の感度も支持点から計算する。線探索中は対応点・支持点集合・重みを固定し、次の外側反復で更新する。

建物の水平・直交方向が成立する場所には、任意の追加観測を用意している。汎用の既定設定では無効。

```yaml
lio:
  temporal:
    consistent_deskew: true
    structure:
      enabled: true
      sigma_deg: 0.5
      max_angle_deg: 8.0
      min_planes: 8
```

鉛直方向には初期化済みの重力を使い、水平方向は最初の利用可能なスキャンの壁法線から求める。90°周期の方向集中度が0.85以上で、十分な壁面が存在するときだけ方向を確定する。以後は各スキャンの平面法線とこれらの方向の差を観測する。方向から8°以上離れた面や、支持面が不足する方向には拘束を加えない。同一方向の重みの合計を制限し、同じ面の分割・密度で観測情報が増えないようにする。

これは水平な床・天井と直交する壁を仮定した**構造の事前知識**であり、通常のLIOだけから得られる観測ではない。斜面や斜めの壁が多い場所、異なる方位の建物をまたぐ走行には適さない。位置・床の高さ・階高・帰着位置の値、再訪認識、ループ拘束は使用しない。構造拘束を無効にして効果を比較できる。法線から建物方向を拘束する考え方の参考: [Peasley et al., Accurate On-Line 3D Occupancy Grids Using Manhattan World Constraints](https://dellaert.github.io/files/Peasley12iros.pdf)。本実装は既存時間窓の生点群因子へ接続した独自実装。

`temporal_window.csv` の `structure_planes` は最新スキャンの採用面数、`structure_rms_deg` は重み付き方向残差、`structure_information` は採用した方向の重みの合計。採用面がない場合はいずれも0。

`imu.gyro_bias_cov` / `imu.accel_bias_cov` で従来ハードコードされていたbias駆動雑音を設定できる。単位系は既存のIMU処理に合わせたサンプル分散であり、連続時間の雑音密度をそのまま代入しない。初期bias共分散とは異なる設定。

明示したYAMLで通常のRViz再生を行うには `reconstruct_raw.sh BAG --params YAML --lio-only --rate 0.25` を使う。既存RVizの表示設定は変えない。

`reconstruct_online.sh BAG NEW_OUTPUT --params YAML --lio-only` は同じfrontendに時系列順でbagのデータを渡し、得た各時刻の推定姿勢のまま `export/map.ply` と `export/trajectory.tum` を保存する。実行ファイル名は既存の `fastlivo2_offline` だが、このスクリプトは後処理最適化を呼ばない。`evaluate_online.py` も位置合わせ・ループ検出・軌道補正を行わない。部屋評価の既定区間は本データセット用の4–12秒と632–648秒で、他のbagでは `--start-room A B --return-room A B` を指定する。対応する点群の見え方が異なるため、最近傍距離と15 cm以内の割合を併記し、近距離点だけの面RMSEを絶対精度と解釈しない。


## 面の法線・位置を含めた同時推定（比較用）

`lio.temporal.structural_landmarks: true` は、各面の法線の2自由度と距離 `d` も未知数にする比較用経路。
`consistent_deskew: true` と `structure.enabled: true` が必要で、`persistent_map` とは併用しない。
既定では無効。方向推定が成立しない初期スキャンでは明示的に停止する。

生の点に対する残差は `nᵀ(R x(v,bg,ba) + p − p_anchor) − d`。
`p_anchor` は時間窓内の基準姿勢の**推定位置**で、固定座標や既知位置ではない。
姿勢・速度・biasの15状態と面の3自由度を同時に更新する。
初期に構造方向と整合する面には `structure.sigma_deg` に従う法線のpriorを一度だけ与える。
斜面などの一般平面にも自由な法線・距離を持たせ、構造方向と違うという理由では捨てない。
この経路では従来のスキャン間点–面因子とスキャンごとの法線方向因子を追加せず、同じ点を重複して拘束しない。

面の各voxelから、面内に広がりのある6点の実測点を個別時刻のまま使う。
初回の対応は法線角度・面間距離 `min(0.12, max_residual)` m・既観測範囲から2 m以内で決め、
原則として構造方向の分類が同じ面を対応させる。信頼できる構造面の観測を一般面が吸収し、方向priorを迂回することを防ぐ。
スキャン内では対応を固定する。同一面・同一スキャンの情報は50点相当に制限する。
位置や階高を指定するpriorは加えない。古い姿勢を周辺化したpriorには、面との相互項も保存する。
時間窓内で観測されなくなった面は、その法線・距離と相互項を平方根形式で周辺化して消去する。
再びその場所へ戻っても、古い面の再認識による拘束は作らない。

2026-10-01に、面距離を世界原点から表す旧実装の周辺化で、絶対位置の不確かさを
不当に減らす問題を合成データで確認した。現在の距離は基準姿勢からの相対量である。
基準姿勢を窓から除く前に `d_new = d_old + nᵀ(p_old − p_new)` へ変換し、
priorの法線・距離・両姿勢の交差項も変換してから周辺化する。
これにより、全姿勢を同じ量だけ並進してもLiDAR・IMUの観測情報は変化しない。
新しい位置の拘束や帰着位置の指定は加えていない。

初期の位置共分散だけに `I m²` を加える独立した6秒の移動試験では、旧表現で
位置差6.683 mmが発生し、分散の差も `[0.996723, 0.997694, 0.999484] m²` へ減少した。
相対表現では位置差は約`2.94e-13 m`、分散差は`I m²`から最大`3.95e-11 m²`の範囲に収まった。
この試験は実走行の地図精度の証明ではなく、推定器の整合性を確認するもの。
[成分別の結果](diagnostics/online-20260930/relative-plane-gauge-validation.json)、
[合成試験ログ](diagnostics/online-20260930/relative-plane-prototype.log)。
周辺化と線形化による観測可能性の変化については
[Huangらの解析](https://doi.org/10.1177/0278364909353640)も参照。
今回の実装はFEJの導入ではなく、並進の不観測方向が一定になる座標表現への変更である。

priorの座標変換は、恒等でない回転3列・法線2列だけを計算する。
858列の独立benchmarkでは128.4 msから4.0 msへ減り、旧計算との最大要素差は`1.11e-16`だった。
処理全体の速度保証ではない。変更前後の実データ60秒LIO・LIVOの状態と共分散は、ログの保存精度で一致した。
[計算時間と数値差](diagnostics/online-20260930/prior-factor-benchmark.log)。

併せて、歪み補正は終端フレーム内で積分し、世界位置の加算・減算を除いた。
IMU因子のJacobianは解析式とし、非ゼロ残差・biasの数値微分との一致を試験する。
面の支持範囲の2 m境界には1 nmの丸め誤差対策を入れ、境界外1 µmの対応は従来通り拒否する。

この経路で `plane_uncertainty: true` を指定すると、構造面を新規登録する際に法線の不確かさも判定する。
平均法線と構造軸の角度に、法線共分散の最大標準偏差の2倍を足し、その値が
`structure.max_angle_deg` 未満の場合だけ構造方向priorを作る。信頼できるpatchを先に処理する。
角度だけが軸に近い不確かなpatchは、既に確立した同じ方向の構造面を観測するか、
自由な法線・距離を持つ一般面として残す。点を一律に捨てる処理ではない。
法線の不確かさが大きい狭い6点のpatchから、非常に強い構造priorを作る問題への修正である。
生点の残差へ同じ法線共分散をさらに足すことはせず、面自体の未知量と状態との相関を通して扱う。
既定は無効。実データでの根拠と評価状況は [不確かな面の分析](diagnostics/online-20260930/WEAK_PLANES.md) を参照。

同時に保持するランドマーク数は `max_landmarks`（既定256、上限512）で制限する。
上限では新しい面の登録を止めるため、`temporal_window.csv` の `landmarks` で確認する。
数値微分、静止シーン、斜面の保持、面と姿勢の相関を含む周辺化、廊下方向の不確かさを回帰試験する。
headless readerが保存した姿勢・点群を走行後に書き換えない。通常ROSのPathは、時間窓に残る姿勢を逐次更新し、周辺化後の履歴を固定する。実データでの採否には全区間の未補正点群による評価が必要。

最初に試した法線固定・直交面だけの版は、廊下を安定化した一方、階段下降で約1.5–1.9 mの高さ誤差が残った。
法線を固定する版を完成版として扱わない。一般平面を含めた版でも下降後の高さ誤差は残っており、全区間比較を継続している。

## 加速度の飽和

`lio.temporal.accel_saturation` は入力のSI単位変換後の軸別しきい値（m/s²）。0が既定で、この機能を無効にする。
有効時、隣り合う測定のどちらかがしきい値に達した軸では、事前積分の加速度分散を
`accel_saturation_variance`（既定2500 (m/s²)²）以上へ上げる。
補間した境界にも元の測定のピークを保存し、平均によって飽和を見落とさない。
`temporal_window.csv` の `saturated_imu_intervals` は直前更新から今回までの影響を受けたIMU積分区間数。
失われた加速度波形を復元するものではない。非飽和時の計算は従来どおり。
実データの根拠・限界は [加速度飽和の分析](diagnostics/online-20260930/IMU_SATURATION.md) を参照。

## 画像を弱い並進方向の補助に限定する比較モード

`lio.temporal.visual_degenerate_translation: true` は、最新LiDARの対応面の世界法線から
`Σ w n nᵀ` を作り、最大固有値に対して `visual_degeneracy_ratio`（既定0.05）未満の並進方向へ画像を融合する。
面ランドマーク方式では、別の保持スキャンからも観測されている面だけをこの判定に使う。
新規に生成した面の自己対応を、並進が観測できた証拠として数えない。

画像の回転と他の並進成分は、その画像因子内の未知量として平方根QRで周辺化する。
単にJacobian列を0にすると、取り除いた成分の画像誤差が残した成分へ漏れるため、その方式は使わない。
全並進方向がLiDARで観測されていれば画像因子を入れず、地図への特徴追加は継続する。
`temporal_visual.csv` の `visual_rank` に実際に融合する画像因子のランクを記録する。
状態の相互共分散を通じた他成分の修正まで禁止する処理ではない。

既定は無効。完全な共同photometric BAへ変更する機能でも、外部較正の誤りを補正する機能でもない。
一般の6自由度運動で常に精度が上がるとは限らないため、実bagの全区間比較で採否を決める。


### 画像候補点とLiDAR因子の選択を分ける比較（2026-09-30）

`lio.temporal.visual_full_points: true` は、画像の特徴選択へ渡す点を
LiDAR最適化の `max_source_points` に連動させず、現在のスキャンで面法線を持つ全点から作る。
VIO側は従来どおり画像の各gridでShi-Tomasiスコアにより特徴を選ぶ。
LiDARの因子数、時間窓、過去の軌道、RViz表示形式はこの切替では変えない。
既定値はfalse。`temporal_visual.csv` の `candidate_points` は画像処理前の候補数、
既存の `pixels` は実際の画像残差に使われた画素数を記録する。
候補数が増えたことを精度向上と同一視せず、全区間の未補正点群で比較する。


### 画像特徴検索・パッチの境界検査（2026-09-30）

画像特徴のvoxel登録と検索は、負座標を含めて同じ `floor(position / 0.5)` を使う。
検索時だけfloor後にさらに1を引いていた不一致を修正した。
同じ画像・特徴を世界座標で平行移動しても取得できる回帰試験を追加している。

画像更新は各反復で現在の投影位置と `level + search_level` から実際の参照範囲を検査する。
画像勾配の差分・補間で読む周囲画素も範囲に含め、無効な特徴の残差・Jacobian行はゼロにする。
`temporal_visual.csv` の `invalid_patch_evaluations` は、その画像の全level・反復で除外した
特徴評価の延べ回数。異なる特徴の個数ではなく、同一特徴の反復分も含む。
`pixels` は最終採用したlevel 0の有効画素数である。

特徴を生成・検索するときは、投影前にカメラ座標の深度が正で有限かを確認する。
負の深度でも透視投影の数値は画像内へ入ることがあるため、画面内判定だけでは不十分。
姿勢更新後に点が視野外へ出た場合も、その画像を新しい参照パッチとして登録しない。
候補点数 `candidate_points` はVIOへ渡す前の点数であり、これらの視野検査で除く点も含む。


## 画像の参照姿勢を含む比較モード（検証中）

`lio.temporal.visual_joint_reference: true` は、各画像特徴の生成時姿勢と現在姿勢を
同じ画像因子に含める。既定値はfalseで、forward composition
(`vio.inverse_composition_en: false`) が必要。画像間の相対情報を保持し、
窓から参照姿勢を除く際には相互共分散を含めて周辺化する。
参照姿勢が窓外になった特徴は再利用せず、新しい測定点で置き換える。
参照パッチは生成時画像へ固定する。`temporal_visual.csv` の `reference_poses` は
画像尤度の生成に使った参照姿勢数（弱方向選別・更新受理前）を記録する。

これは固定の測定深度とfrontendの局所patch warp近似を使う比較実装であり、
深度・画像warpまで再線形化する完全なphotometric BAではない。
画素相関・較正誤差を完全にモデル化するものでもない。全走行の精度改善は未確認。

参照姿勢を `R_a, p_a`、生成時IMU座標の点を `q_a` とすると、点の世界座標は
`P = R_a q_a + p_a` となる。現在姿勢の世界並進Jacobianを `J_t` としたとき、
参照姿勢の右摂動に対するJacobianは `J_a = [J_t R_a [q_a]×, -J_t]`。
現在・参照の両位置を同じだけ動かした際の画素変化は0となる。
露光を消去するQRでも両姿勢の列をまとめて扱い、この相互項を捨てない。
`visual_degenerate_translation` が有効なら、全参加姿勢の回転と強い並進を周辺化し、
弱い並進の相対情報を残す。

試験では、参照点の有限差分、露光消去のdense Schurとの一致、並進のgauge、
参照姿勢を窓から除いた後の共分散を確認した。ゼロinnovationでの情報保持と、
非ゼロinnovationによる非線形応答は別に検査する。後者では過去のIMU因子を
再線形化する全履歴窓と、一次の周辺化priorを持つ短い窓は完全には一致しない。
画像特徴が全て期限切れとなる場合も、空地図の早期returnの前に描画用の非所有参照を消去する。

先頭60秒の3条件は正常完走し、有限性と共分散の正定値性を確認した。
参照姿勢を無効にした条件は、変更前の全区間実行の先頭とLiDAR283更新・画像282更新の
全共通数値列が一致した（処理時間を除く）。これらは初期安定性・切替の検証であり、
帰着部屋の精度を保証する結果ではない。

### 連続画像の特徴追跡による比較モード（実データ検証中）

`lio.temporal.visual_reprojection: true` は、前の画像からKLTで追跡した2D位置と、
その時点のLiDAR深度による再投影残差を使う。既定値はfalse。
往復追跡のずれ、画像の範囲・輝度差、PnPの合意集合を検査する。
PnPが出した姿勢をフィルタへ代入するのではなく、各残差の現在・参照姿勢のJacobianを同時にQR圧縮する。
画像単独で共通の位置・姿勢を決めない。参照が窓外、画像間隔が0.35秒超、追跡が不足する場合は拘束を追加しない。
各現在フレームで新しい実測深度をseedするため、再訪地図との画像照合は行わない。

この比較は歪み係数0のpinhole画像を対象とする。現bagのCameraInfoはこの条件を満たす。
追跡のpixel標準偏差1、参照ray方向の距離標準偏差0.03mでwhitenする。
深度を参照姿勢へ結びつけ、姿勢の相互情報は保持するが、各点の深度を自由変数にするBAや外部較正推定ではない。
測定時のdeskew済み深度、pixel noise、較正についてのモデル近似は残る。

画像因子を追加するまで前フレームを保持し、融合後に非キーフレームを周辺化する。
最初の比較は画像0.2秒・keyframe0.19秒・2秒窓・max_nodes11で行った。
周辺化順を整理した版ではkeyframe0.5秒・max_nodes6も検証している（詳細は後述）。
`visual_degenerate_translation: true` との組合せでは、LiDARで弱い並進方向への情報だけを使う。
`temporal_visual.csv` の `tracked_features`、`reprojection_inliers`、`tracking_dt` で追跡段階を確認できる。
これらの点数と、最終的に融合する `visual_rank` は区別する。幾何形状が十分ならrank0になる。

合成の2つの奥行きの画像を実際に追跡する試験で、移動量の向き・大きさ、非identity外部較正での微分、
共通SE3変換に対するgauge、参照期限切れ、画像欠測・低texture、OpenCV RNG復元を確認した。
C++全16試験は成功したが、全走行の帰着精度を実証した段階ではない。一般設定へ自動適用しない。


### 連続画像の参照姿勢と周辺化順

再投影方式では、LiDAR更新時に直前画像の姿勢を一時的に保持し、画像因子を融合した後で
非キーフレームの姿勢を周辺化する。毎画像をキーフレームへ昇格させる必要はない。
`image_interval_sec: 0.2` と `keyframe_sec: 0.5` を分けて設定できる。
画像待ちの間だけ通常の `max_nodes` より最大1姿勢を追加で保持し、欠測しても履歴は増え続けない。
画像因子がpriorに入った後も同じ画像の再融合を拒否する。
再投影方式の画像間隔は0.3秒以下が必要。実際の欠測間隔が0.35秒を超えた追跡は破棄する。

全姿勢を保持するゼロinnovationの基準計算に対し、非キーフレームを画像融合後に消去しても
現在状態の共分散が一致すること、空画像観測・欠測・同一画像の二重融合拒否を試験した。
16件のC++試験に成功。現時点では実bagの60秒比較中で、全区間の精度・計算時間改善は未確定。
以前の「keyframe_secをimage_interval_secより短くする必要がある」という制約はこの修正で不要になった。
