# Laser Mapの表示仕様の復元（2026-09-29）

ユーザーから、Laser Mapは出力されなかったのではなく、表示仕様が変わっていたとの訂正があった。
時間窓の導入とその後の調査で変更した表示要素を確認し、不要な仕様変更を撤回した。

## 変更理由と対応

| 変更した要素 | 当時の理由 | 今回の対応 |
|---|---|---|
| 全走行の累積地図→直近約6秒の局所地図 | 修正前の姿勢で配置した古い点群を残さないため | **撤回**。推定器とは独立した表示仕様であり、時間窓の導入に必須ではない。既存の累積地図へ戻す |
| Laser MapのIntensity→水色のFlatColor | 強度値に依存せず点を見分けやすくするため | **撤回**。表示できない原因を確認しないまま色を変える必要はなかった |
| mapのVolatile→Transient Local | 停止後に表示を有効にした場合にも最後の地図を届けるため | **撤回**。今回ユーザーが報告した問題への対処としては不要 |
| 最初のキーフレームで即時配信 | 起動直後の地図待ちを減らすため | **撤回**。従来の`map_publish_interval`に従う |
| Registered ScanのDecay Time 10→0 | 修正前後の点群が重なるのを避けるため | **撤回**。従来の10秒表示を復元 |

RVizのLaser MapとRegistered Scanの設定ブロックは、前回調査開始時のバックアップと全項目一致する。
それ以前からあるAlpha、点サイズ、Intensityの自動範囲などをgit HEADへ一括で戻すことはしていない。

軌道の修正済みキーフレームと古い中間姿勢の混在を除く修正、およびTrajectoryのBuffer Length 1は維持した。
これは3.75 mの人工的な段差や、異なる修正時点の全軌道の重ね描きを避けるための不具合修正。
軌道のTransient Local配信も維持している。Laser Mapの表示範囲・色には影響しない。

## 復元した実装

`LIVMapper_temporal.cpp`の6秒分のキーフレームを集める配信処理を削除し、最新スキャンのworld点群を既存の
`update_and_publish_map()`へ渡すようにした。この関数は、全走行の点を`publish.map_voxel_size`のvoxelへ蓄積し、
`publish.map_publish_interval`ごとに`/Laser_map`へ配信する。表示用の累積地図を推定器の因子としては使わない。

地図の配信QoSは従来のReliable / Volatile / Keep Last 1、RViz側もVolatileに戻した。
既定の実行設定ではvoxel 0.5 m、10スキャンごとに配信する。

累積点群は各スキャンの出力時点の姿勢を使う。後から過去の点群を再配置する機能を追加したものではない。
今回の変更は表示仕様の復元であり、推定精度の改善ではない。

## 精度評価の訂正

ユーザーの比較では、時間窓への変更により従来より全区間の地図・軌道精度が大幅に悪化した。
「問題が残っている」という当初の表現を訂正し、**変更による退行**として記録した。
後退がなくなったことや軌道表示の不具合を修正したことを、全体精度の改善の根拠にはしない。
今回、推定器の残差・重み・周辺化・較正は変更していない。

## 反映方法

Docker内のワークスペースでC++再ビルド済み。推定ノードを再起動し、RVizで`config/fast_livo2/fast_livo2.rviz`を再読込みする。
通常の`reconstruct_raw.sh`を新しく起動すれば、このRViz設定を読み込む。

## 検証

- CTest 7/7成功。
- 同じraw bagを12.200秒まで実再生し、地図を9回受信。全点が有限で、frameは`camera_init`。
- 地図のvoxel数は1,168→1,354。連続する地図の間で失われたvoxelは0。
  最初の1,168 voxelは8.037秒後の地図にも全て存在し、推定窓の6秒を超えて保持された。
- 復元前後の91スキャンのwindow CSV 494列（solve_msを除く）、states CSV 741行20列は文字列表現まで完全一致。
- RVizのLaser Map・Registered Scan設定は、前回調査開始時のバックアップと全項目一致。
- ヘッドレスでの配信試験であり、実際のRViz画面の描画と全648秒の再生は検証範囲に含めない。
