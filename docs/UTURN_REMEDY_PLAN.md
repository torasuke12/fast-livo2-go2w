# Uターン後の後退に対する改訂対処計画（2026-09-28）

**実装追記:** T1の時間窓経路を`feat/temporal-lio-window`へ実装した。
同じbagの360秒再生では持続的な後退を再現しなかった。
[実装・使い方](TEMPORAL_LIO.md)、[検証結果](TEMPORAL_LIO_VALIDATION.md)を最新状態とする。
以下の対処計画は背景と未実施項目の整理として残す。

**2026-09-29改訂:** ユーザーの比較では、時間窓への変更によって従来より全区間の地図・軌道精度が大幅に悪化した。「問題が残る」ではなく変更による退行として扱う。
[最新分析・比較順序](TEMPORAL_QUALITY_ANALYSIS.md)を優先する。確定した軌道出力の不具合は修正済み。
次は歪み補正と状態Jacobian・周辺化の整合性、直前1枚への照合依存を検証し、全体地図の再配置・再訪拘束へ進める。
「時間窓を入れた」「360秒で後退しない」だけでは主対策の完了としない。

**優先順位の更新:** [320秒以前の比較](TEMPORAL_EARLY_REGRESSION.md)に基づき、初期化直後からの退行を先に扱う。
時間窓だけでなく既存の地図初期化・LIVO voxel-plane照合まで別実装へ置き換えた影響を、個別の比較で切り分ける。
初期化・観測処理の比較→180–300秒の形状→320秒後と階段の順で評価する。

**法線ゲート、続くvoxel-plane切替でも320秒付近の後退は残った。主対策を時間をまたぐ姿勢・速度・biasと地図の整合へ移す。**
voxel-planeを観測・地図の基盤として維持するが、品質を使うX-ICP拡張（R1b）の完成を時間窓（R2）の前提にしない。
新たに確認した点共分散の座標系不整合は限定修正として独立比較する。較正・IMU雑音・閾値の一括調整は行わない。

本書は[voxel-plane実行の分析](VOXEL_PLANE_FAILURE_ANALYSIS.md)を優先し、[法線ゲートONの分析](NORMAL_GATE_FAILURE_ANALYSIS.md)も根拠とする。
前版の「R1a→R1b→R2→R3」という必須順序を第6節の比較計画へ改めた。
voxel-plane自体は既存実装。**R1aの設定切替・記録対応を実装済み**。
実行手順と検証範囲は[voxel-plane切替](VOXEL_PLANE_SWITCH.md)を参照する。
R1aは335.999秒までの完了データを解析済みで、持続的後退は321.10秒から。R1bは未実装、R2はT1として実装済みだが精度面の課題が残る。

新しい検証では床候補の約91–96%を採用できても、180–310秒のbias Xが+0.565 m/s²、pitchが+5.360°変化した。
315–320秒の予測前方加速度は−0.718 m/s²。処理済みIMUは前回共通区間の66,582行が全列一致した。
対応不足だけを主因とする説明を改め、位置残差をbiasへ吸収する経路と、姿勢・地図の共有誤差を扱う。

## 1. 何を修正するのか

以下は法線ゲート段階で得た所見。voxel-plane後の新しい数値と修正順序は冒頭・第6節を優先する。

| 法線ゲート段階で確認した問題 | 計画の修正 |
|---|---|
| 後退開始は321.10→322.80秒。360秒前に大きく発散 | 数秒の遅延を成功とせず、持続的なIMU予測誤差を止める |
| 200–220秒、法線判定不能群13.5%が前方情報の63.8%を占めた | 判定不能点を同じ観測分散で無条件に信頼する扱いを見直す |
| 180–310秒のbias X増加+0.359 m/s²の約半分が判定不能群の寄与 | 対応品質の重みと、位置からbiasへ流れる更新を両方扱う |
| 300–310秒の床面相互差0.58°、world傾斜は双方約5° | 法線一致だけを姿勢・地図の正しさの根拠にしない |
| 床点の74.7%が地図平面適合で棄却される区間が残った | 信頼できる面を維持・再利用できる地図更新が必要 |
| 今回の初反転では前方に近い並進軸がX-ICP NONE | 観測不足時に偏ったIMU予測を維持する限界を扱う |
| ゲイン・ヘッセ・共分散の保存値との整合検査はPASS | 観測モデル・座標系そのものの正しさを別に検査する |

残差の小ささ、法線一致、単一スキャンのFULL判定、共分散の正定値性は別の性質を確認している。
どれか一つで推定全体が正しいと判定しない。

## 2. 採用方針：既存voxel-planeの面共分散を使う

**LIOの対応付けを`lio.correspondence_mode: voxel_plane`へ切り替える方針とする。**
FAST-LIVO2でVIOにも利用されているvoxel-plane地図を、LIOの観測にも使う。
`common.img_en`を有効化しなくても利用できる。ikd-treeの5近傍面へ独自の品質モデルを追加する案は置き換える。

### 既存実装で利用できる部分

[voxel_map.cpp](../humble_ws/src/fast-livo2/src/voxel_map.cpp)を確認した。

- `VoxelOctoTree::init_plane`が点群の平面性を調べ、法線・中心の6×6共分散`plane_var_`を計算する。
  平面にならない領域は階層voxelへ分割する。
- `BuildResidualListOMP` / `build_single_residual`が近隣voxelの面を探索し、面の広がり、
  不確かさで規格化した距離、尤度から対応を選ぶ。
- `StateEstimation`がvoxel-plane経路で使う残差分散は、現実装では次式。

  ```text
  R_i = 0.001 + J_plane Σ_plane J_planeᵀ + nᵀ Σ_point_world n
  W_i = 1 / R_i
  ```

  点の分散には距離・ビーム角度のモデルを使う。面の分散は地図点の分散から伝播する。
  対応候補のゲートで使う分散と、状態更新で使う上式は完全に同じ式ではないので、診断でも分けて記録する。
- 重み`R_inv`は通常の更新とX-ICPの**制約付き更新**へすでに渡る。
  残差・ゲイン・事前事後共分散・結合ヘッセの集計／採用点診断も共通経路にある。

### 追加作業と現在の状況

1. **X-ICPの退化判定とPARTIAL補助問題へ、面の不確かさを反映する（補助対策。R2の必須前段から外す）。**
   現`xicp::detect(points, normals, config)`は重みを受け取らない。
   バックエンドを切り替えるだけでは、低品質な面も判定時には同じ強さで数えられる。
   更新に使う`R_inv`を明示的に渡し、方向の情報評価・対応選別・PARTIALの目標補正の計算を整合させる。
   単位法線を単に重み倍して渡さない。従来の点数ベース閾値250/180/35も無条件に流用しない。
   回転・並進の結合6×6情報を併記し、単位の違いを規格化して確認する。
   PARTIALの目標を同じ残差から作る点は維持し、変更後のゲインとJoseph共分散の整合を検査する。
   面・点共分散の有限性と半正定値性、分散を増やしたときの情報の減少、座標変換・法線符号の不変性を確認する。
2. **voxel-plane用の幾何診断を追加する（R1aで実装済み）。**
   元スキャン点との対応、参照voxel・層・面ID、法線・中心・面共分散、支持点数・固有値、
   ゲート用分散、更新用分散の内訳、棄却理由を記録する。
   同じ面を参照する点数と情報量、面更新停止の状態も確認できるようにする。
   ikd-treeの「実際の5近傍」をvoxel-plane用データに見せかけず、方式を識別できるschemaにする。
3. **起動・captureを方式に対応させる（R1aで実装済み）。**
   `lio.normal_consistency.enabled=true`はvoxel-planeでは引き続き拒否する。初回比較ではOFF。
   `lio.diagnostics.geometry.enabled=true`はschema-v4で利用可能。
   `--correspondence-mode`で方式を上書きでき、`--capture-diagnostics`の派生params生成・実効設定確認・解析も対応済み。
   MID360の元YAMLはvoxel-planeへ切替済み。実行時の上書きは別の派生YAMLへ保存する。
4. **既存の初期化と面更新の挙動を確認する。**
   voxel-planeには`TryInitializeVoxelMap`による複数スキャン蓄積と面法線の広がり判定がある。
   初期化完了時刻・支持面数・更新開始を記録し、タイムアウトだけで初期化を通さない。
   面は`max_points_num`到達時に更新を停止する実装なので、古い不整合面が保持される問題も測定する。

切替済みMID360設定の中心は以下。検証用captureも利用できる。

```yaml
lio:
  correspondence_mode: voxel_plane
  normal_consistency:
    enabled: false
```

初回は既存の`voxel_size=0.5`、`max_layer=2`、`max_points_num=100`、
`dept_err=0.02`、`beam_err=0.05`を基準とし、切替と同時に雑音・較正・IMU設定を調整しない。
`fastlio_filter_size_map`はvoxel-planeの分解能には使われない。

### 切替で解決したと扱わない部分

面共分散が存在しても、同じ姿勢で生成した点どうしの相関や、姿勢・地図の共通の傾きまで正しく表す保証はない。
現`plane_var_`は各点の分散伝播を足し合わせる実装で、点間の相互共分散を保持しない。
voxel-plane単独で根治を約束せず、後述の時間的な状態整合と地図更新を継続して評価する。
既存のsource法線ゲートをvoxel-planeへ移植するかは、今回の切替結果を見て別に判断する。

上記はリポジトリの現在の実装に基づく。論文の観測モデルがそのまま全部実装されているとは扱わない。
[FAST-LIVO2原論文](https://arxiv.org/html/2408.14035v2)

## 3. 根治の中心：時間をまたいで姿勢・速度・biasを整合させる

**姿勢・biasの問題を「対応を直しても残った場合の後回し」にしない。**
単一スキャンのposeヘッセだけでは、加速度biasと傾きを時間を通じて区別できるか分からない。
廊下の進行方向の情報が弱いとき、姿勢の誤差による重力補償とbiasが相殺して、
現在の位置残差だけは小さくなる状態を許さない設計が必要。

本命は、**複数時刻の姿勢・速度・gyro bias・accel biasを、IMUと信頼できる面観測で同時推定する短い時間窓**。
地図の取得姿勢・面の履歴を保持し、修正後の歪み補正・面推定をやり直す最小限の地図管理を同時に含める。
誤った固定地図と強い事前を真値として使う窓を足すだけでは、同じ不整合を再現し得る。
窓長は秒数を先に固定せず、直進・ターンの励起、計算量、情報の蓄積を測って決める。
今回の記録は問題区間を選べるが、最適な窓長・閾値までは決められない。

- IMU伝播または前積分とLiDAR残差を同じ窓に入れ、位置だけ合わせてbiasを動かす更新を避ける。
  gyro biasとaccel biasを分け、姿勢と速度の変化も使う。
- 観測由来の情報と既存の事前分布を分け、他の状態を周辺化した情報から、
  bias・姿勢の識別しにくい組合せを調べる。事前が強いだけの固有値を新しい観測情報と数えない。
- 情報が不足する方向では、biasが精密に推定できたと扱わない。
  現ESKF内の段階的な案として、観測不足方向のbias補正を抑えるSchmidt型の更新などを比較する。
  一律固定ではなく、実際のゲインと対応するJoseph共分散・相互共分散・姿勢接空間変換を揃える。
- 最後の値を凍結するだけでは、すでに誤ったbiasは直らない。
  情報が回復したときに過去の姿勢・biasを再評価し、局所地図も再線形化・再構築できるようにする。
  生のスキャンと時刻・取得姿勢を保持する必要がある。
- IMUの単位・雑音モデル・離散化・時刻・外部較正は独立に確認する。
  今回のログだけで初発原因を較正不良と断定せず、`dt²→dt`などを根拠なく同時変更しない。

時間窓も、本当に情報のない方向を観測可能にするものではない。
X-ICPのNONEでLiDAR補正を止めても、偏ったIMU予測の回復にはならない。
原論文も初期予測の悪化と退化が重なる限界を述べている。
[X-ICP原論文](https://arxiv.org/html/2211.16335v4)

## 4. 地図を固定された真値として扱わない

観測品質と時間窓の変更に合わせ、**地図点の取得時の姿勢・品質・複数回の支持を保持する**。
最初の実装範囲は安定した局所地図と新規候補の分離、および採用・保留・置換理由の記録。
その後、姿勢の修正に追従して局所地図を作り直せる構造へ進める。

- voxel-planeの支持点・面共分散・更新履歴を基礎に、異なる時刻からの支持を使う。
  `VoxelOctoTree::UpdateOctoTree`の再推定・更新停止と、上限到達時の支持点解放を見直し対象にする。
  ikd-treeのボクセル中心距離による代表点保持の修正は、新方式の実装対象から外す。
- 不確かな姿勢で作った面が、すぐ次スキャンの強い観測となる循環を抑える。
  現在の小さな`P`だけで安全と判断せず、観測不足・残差の偏り・面の支持も使う。
- ゲートで棄却された点が必ず悪い計測とは限らない。地図が誤っている場合もある。
  採用対応点だけの地図追加や、最新点の無条件優先にはしない。
- 床の棄却率、面の厚み、取得姿勢別の食い違い、保持点の年齢・取得距離を比較する。
  床の水平は強制せず、壁や実際の坂でも成立するモデルを使う。

voxel-planeの`lio.voxel_size`と階層深さは、分解能感度の比較として扱う。
旧案の`fastlio_filter_size_map`の0.5→0.2 m変更は、新方式の比較には使わない。
点密度が増えただけの改善と、面の信頼度が上がった改善を区別する。

## 5. 情報不足が続く場合の独立した拘束

状態と地図が同じ誤差を共有する場合、相互比較だけでは決着しない。
時間窓でも前方速度・傾き・biasが区別できない区間には、独立した運動情報が必要になる。

- **静止拘束**: 本当に静止している区間だけで速度ゼロを使う。
  加速度normやジャイロが小さいだけでは、等速直進と静止を区別できない。
  映像・操作・別センサーなどでも停止を確認できる条件を決める。
- **カメラ**: 既存bagには画像とcamera_infoがある。
  時刻と外部較正を確認し、視覚観測が問題区間の独立した運動情報になるか別比較する。
  暫定較正のままLIVOをONにするだけでは成功条件を満たさない。
- **車輪速度など**: 今回bagには車輪・関節オドメトリがなく、現データでは検証できない。
  追加取得する場合も接地・スリップ・走行モードに対応するモデルが必要。前進符号の強制で代用しない。

今すぐ新しい実機走行を要求するものではない。
まず既存bagで観測品質と時間的な情報不足を切り分け、必要な拘束を決める。

## 6. 次の比較順序と合否判定

| 比較 | 変更 | 判定したいこと |
|---|---|---|
| R1a（完了） | 既存voxel-plane＋既存の観測重み・X-ICP判定 | 床対応は改善したが321.10秒から後退。根治には不合格 |
| C0（限定修正） | 照合・初期地図・地図追加の点共分散を正しい座標系で伝播 | `−R[p_I]×`の有限差分、world回転に対する共変性、再生への影響。単独で根治と決めない |
| T1（主対策、旧R2） | 姿勢・速度・両biasの時間窓＋取得姿勢と面の履歴＋局所地図の再評価 | ターン前の不整合をbiasへ吸収せず、ターン後の持続的な予測減速を防ぐか |
| M1（T1と整合させる） | 同じ面・取得姿勢を共有する観測の相関と周辺化を扱う | 点数の増加だけで地図の共有誤差まで確実と扱わないか |
| R1b（独立した補助対策） | 品質を使うX-ICP判定・PARTIAL補助問題 | 信頼度の低い方向を過大評価しないか。T1の開発開始条件にはしない |
| R4 | 残る情報不足に、検証済みの独立した拘束を追加 | LiDAR/IMUだけで識別できない方向を実測で支えられるか |

最初の比較では法線ゲートをOFF、画像更新もOFFとする。
初期化後から約60秒の健全性を先に確認し、その後360秒まで継続する。短時間の有限値出力だけを成功としない。
時間窓と再構築には共通の履歴管理が必要。局所地図の再評価を完全に別の後工程へ追いやらない。
C0の回転・位置交差項は接空間とPSDを揃え、ゲート／地図の不確かさを観測Rへ二重計上しない。
T1ではターンの励起を含む窓長と周辺化事前の情報を検査する。biasの一律固定や最後の値の凍結で代用しない。
各段階で変更した条件を明記し、閾値・較正・IMU雑音をまとめて変えない。

同じbagの先頭からLIO-onlyで開始し、少なくとも360秒まで確認する。
300秒からの再開では、それ以前に蓄積した姿勢・地図・biasへの効果を評価できない。
入力・初期化・再生条件を揃え、通常Logを隔離する。

1. **観測**: 品質別の情報・ゲイン寄与、結合ヘッセ、床棄却、面の厚みと支持。
   誤観測を除いて固有値が小さくなること自体は失敗ではない。
2. **ターン前**: 180–310秒、特に今回増加の約91%を占めた220–310秒の姿勢・床面指標の乖離、bias補正、時間窓で識別できる方向。
   biasが小さいことだけを成功条件にしない。
3. **ターン後**: 持続的な負の予測加速度、予測と観測補正の収支、継続的後退の解消。
   数秒の発症遅延では不合格。実際の停止・後退は映像等と区別する。
4. **整合性**: 使用したゲイン・制約・事前事後共分散を再検証する。
   可能なら独立した速度・姿勢と比較し、不確かさの妥当性も確認する。
5. **負荷**: 処理済みIMU、欠落、遅延、メモリ。巨大な全点ログの負荷も分離する。

360秒を通過したら全bag、次に較正を確認したLIVOで検証する。
正解軌跡がない限り、後退症状の解消と絶対精度の実証は区別する。

## 7. 追加データの境界

**今回の失敗理由と改訂案の整理には、現データで足りる。** 法線ゲートONとvoxel-planeは先頭からの幾何を取得済み。
次の対策効果は既存bagの再生で評価できる。
