# 2 bagにおけるLIO・LIVOの環境別証拠

2026-11-03。目的は推定精度の改善ではなく、**同じ入力で画像を使う／使わない場合に何が変わり、その変化を環境と内部診断からどこまで説明できるか**を明確にすること。構成・完走範囲・実行ファイルの定義は[12条件の台帳](LIO_LIVO_TWO_BAG_EVIDENCE_20261030.md)に従う。真値軌道はないので、以下の「ずれ」は別推定器との差または再訪点群の自己整合性であり、絶対位置誤差ではない。

時間窓の4本は保存済みcaptureのみに基づく。[同期解析の全数値](../diagnostic_captures/current_default_temporal_20261101/environment_evidence.json)を生成した[解析コード](../scripts/fast_livo2/analyze_environment_evidence.py)は、姿勢・LiDAR更新・視覚更新・保存キーフレーム点群をbag相対時刻で結合する。軌道は0.1秒刻みの線形補間で比較し、未整列差と20秒の位置・yawだけを一致させた差を別々に記録する。後者は軌道全体への最適整列ではない。点群の指標は各LIO保存スキャンの有限点・20 m以内を使う。画像はbag原本の最も近いフレームから作った[9/7の場面一覧](../diagnostic_captures/current_default_temporal_20261101/scene_sep07.jpg)と[10/20の場面一覧](../diagnostic_captures/current_default_temporal_20261101/scene_oct20.jpg)で確認できる。

## 位置・向き・速度の分岐

対照軌道は各bagの**f281e70 LIO**。10/20では同構成のLIO/LIVOが全行程で近接しており、最新X-ICP LIOもf281e70 LIOと339秒を通じて最大0.362 mの差なので、初期45秒の比較目安にはなる。9/7のf281e70 LIOは約494秒まで速度基準の破綻がない。どちらも真値ではない。**異なる推定経路の開始座標系には固定の向きの差があり得るため、未整列の位置差だけで破綻を判定しない。**

9/7のLIOの未整列差6.85 m（44秒）は、初期yaw差約12°を除くと0.90 mになる。前の台帳でこの未整列差だけを理由にLIOを「不健全」と扱った判断は強すぎた。LIVOは初期姿勢を合わせても大きく分岐する。LIO対LIVOの**未整列**位置差が初めて1 mを超えるのは9/7で24.3秒、10/20で25.5秒。5 m超は26.8秒／31.8秒。9/7では両者のyaw差が小さいままLIVOの並進が逆方向に伸び、30～35秒の推定速度中央値はLIO **1.48 m/s**、LIVO **3.93 m/s**。LIVOは35.6秒に連続する姿勢区間で5 m/sを超え、監督が停止した。

10/20のLIOには20秒時点ですでに対照との約16°の初期yaw差がある。走行後に未整列方位差は約22°となるが、その全量を走行中の方位ドリフトとは呼べない。20秒の姿勢を合わせた44秒の対照位置差はLIO **3.84 m**、LIVO **10.42 m**。30～35秒の推定速度中央値はLIO **1.11 m/s**、LIVO **2.62 m/s**で、LIVOの高さも35秒で約−1.77 mとなる。この区間のLIVOは初期座標系の差を除いても並進・高さに不整合が残る。

10/20は15～25秒の推定速度中央値が両モードとも0.02 m/s以下のほぼ静止区間である。その20秒時点ですでにLIOの対照方位差は16°、LIVOの加速度biasノルムは約0.34 m/s²。前者は座標系の向きの差も含む。したがって、25秒以降に見える屋外地物だけをこれらの差の発生原因とはできない。初期化と、静止中にも累積する観測因子の影響を分けて調べる必要がある。

LiDAR対応点は分岐時にも数百点あり、RMSも急激な桁違いの悪化を示さない。これは**局所面に合うことと軌道が正しいことが別**である証拠。9/7 LIVOではRMSが0.030→0.062 mへ増えるが、有効対応数は1008→939でゼロにはならない。10/20の両モードでもRMSは約0.03 mにとどまる。点群の法線分布や誤対応率はこのCSVにはないため、「廊下の幾何退化が原因」とまでは言えない。

時間窓4本の保存済みLiDAR更新ログでは `saturated_imu_intervals` はすべて0。少なくともこのprefixのbias差を、ログが検知するIMU飽和だけで説明する根拠はない。

LIVOの視覚更新は保存区間でほぼ毎LiDAR更新時刻に実施され、30～35秒も各bagで50回。にもかかわらず有効画素中央値は20～25秒から9/7で**63%減**、10/20でも**63%減**。候補点中央値は同期間に9/7で約708→657、10/20で551→612なので、単純な候補点消失とは異なる。画像の反復模様・反射・屋外の遠景や移動によって視覚拘束の質が変わった可能性はあるが、この記録には対応の正否を独立に判定する真値がない。

視覚更新1回の位置修正ノルム中央値は9/7で20～25秒の**4.4 mm**から30～35秒の**9.3 mm**、10/20では**1.4→2.4 mm**。単発の補正量は大きな位置差を直接説明しない。画像を有効にした経路では、視覚因子の反復適用、IMU bias、後続のLiDAR対応・地図更新が連成する。特に加速度biasの差は分岐前の20～25秒から既に大きい。ただし、この記録だけでは**biasが先に原因となったのか、別の不整合をbiasが吸収したのか**は識別できない。

9/7の加速度bias差は15～20秒にもあり、中央値はLIO **0.04 m/s²**、LIVO **1.03 m/s²**。この時刻の画像には廊下に入る前の室内と廊下の入口が写る。ゆえに25～35秒の廊下形状や反復模様だけで、LIVOの後の大きな速度差を説明することもできない。

LiDAR更新直後の位置共分散対角成分の中央値は、20～25秒に時間窓LIOで概ね**1.0 m²**、LIVOで**5×10⁻⁶～2×10⁻⁵ m²**。30～35秒もLIVOは約**6×10⁻⁶～8×10⁻⁵ m²**のまま。これは推定器内部の線形化した不確かさであり、対照軌道との差や真の誤差の上限を意味しない。LIOとLIVOでは画像因子・周辺化経路も異なるので、数値の大小をそのまま画像の信頼性や較正済み精度と解釈しない。

## 現時点で支持される環境別の主張

1. **この9/7の屋内廊下・最新6秒時間窓の初期区間では、画像有効化は頑健性を改善していない。**LIOよりLIVOの速度・位置差・biasが大きく、LIVOだけが35.6秒に自動停止した。廊下の反復模様と細長い点群形状は同時に観測されるが、失敗の単独原因とは確定していない。
2. **この10/20の屋外初期区間では、初期姿勢を合わせてもLIVOの並進・高さの不整合が大きい。**LIOにも走行中のずれは残るが、20秒の姿勢を基準にした44秒の対照位置差は3.84 mで、LIVOの10.42 mより小さい。未整列yawの約16°は走行前からあるため、それを画像による方位改善と断定しない。
3. **旧f281e70の10/20全行程では、画像の有無による軌道差は小さい。**位置差の中央値0.039 m、最大0.134 m。帰着部屋の15 cm以内重なり率はLIO/LIVOで27.4/29.0%、同じ近接対応の局所面RMSEは0.0627/0.0483 m。一方、220～339秒の高さ標準偏差は0.0023/0.0132 m、加速度biasノルム中央値は0.085/0.489 m/s²。**局所面残差の改善はあるが、停止時の高さ安定性は悪化した。**[旧構成の全数値](../diagnostic_captures/pre_oct1_f281e70_20261020/comparison.json)。重なり率は視点・遮蔽にも左右される。
4. **9/7の旧f281e70全行程では、画像が破綻を防いだとは言えない。**LIO/LIVOの初回連続5 m/s超は493.9/498.6秒で、両方とも出発・帰着点群の15 cm以内重なり率は0%。画像が破綻を約4.7秒遅らせた可能性はあるが、その差を環境一般へ外挿できない。[旧構成の記録](../diagnostic_captures/pre_oct1_f281e70_20260907/FINDINGS.md)。
5. **画像の寄与は構成依存である。**10/20の最新X-ICPではLIOがbag読了した一方、LIVOは75.8秒に速度基準で破綻した。[X-ICPの限定比較](LIO_LIVO_TWO_BAG_EVIDENCE_20261030.md)。これを時間窓や旧f281e70の結果と混ぜて単一の「画像効果」とはしない。

## まだ主張できないこと

真値に対する絶対精度、廊下／屋外という地形カテゴリ全般への優劣、視覚画素低下とbias増加の因果順序、LiDAR法線の退化や画像の誤対応率は未確定。今回の証拠は**同じbag内の対比**を強くし、環境間の一般化は控える。次の分析では新しいreplayより、保存された分岐前のスキャンに対する法線方向の情報行列と、画像パッチの残差・追跡一致を時刻同期して求めるのが有効。推定パラメータを変更して精度を上げる作業は本件の目的に含めない。
